3. 광고와 추적

  2. 초기화 순서는 앱마다 다릅니다.

    • 9개 앱(냉장고 알리미, 백색소음, 뽀모도로, 스크린 디톡스 챌린지, 연휴 알리미, 자세 알리미, 차량 정비 기록, 포트체크, 화분 물주기): SDK 초기화가 앱 화면이 뜨기 전에 실행됩니다. 즉 ATT 창이 뜨기 전에 초기화됩니다. 그중 뽀모도로·차량 정비 기록·포트체크는 초기화 직후 전면 광고 사전 로드도 호출합니다.

8. 보유·파기

  • 앱에 입력한 내용은 이용자 기기에 있고 보유 기간은 대체로 이용자가 정합니다. 다만 주차 타이머의 최근 기록처럼 앱이 최대 개수(20개)를 넘으면 오래된 항목을 자동으로 제외하는 경우가 있습니다(5장). 이용자가 앱 안에서 기록을 지우거나 앱을 삭제하면 기기의 앱 데이터가 삭제됩니다(앱별 삭제 기능의 범위는 확인하지 못함).
  • iOS 기기 백업이나 iCloud 백업에는 앱 데이터가 포함될 수 있으며, 백업에서의 삭제는 iOS 설정에서 하십시오.
  • 이용자가 공유·내보내기로 만든 파일과 수신 앱·클라우드의 사본은 앱을 삭제해도 남습니다. 해당 앱·서비스에서 지워야 합니다.
  • 개발자 운영 서버에는 위치를 저장하지 않습니다. 주차 타이머(현재 세션·최근 기록 최대 20개·즐겨찾기)·미세먼지 앱(즐겨찾기)은 좌표를 기기에 저장합니다(5장).
  • 외부 서비스에 전달된 정보의 보유·파기는 각 서비스의 방침을 따릅니다.
  • 지원 문의 이메일(발신 주소·본문·첨부)은 문의 답변 목적으로만 사용하며 처리 완료 후 1년 뒤 삭제합니다. 파기 대상은 개발자가 보유한 메일·첨부·별도 저장 사본이며, 삭제 후 휴지통도 비워 개발자가 계속 이용하지 않도록 하는 것을 파기 절차로 정합니다. 이메일 서비스의 별도 백업·로그까지 같은 시점에 삭제되는지는 확인하지 못했습니다.
  • 현재 근거에서 지원 문의 메일에 적용되는 별도의 법정 보존 기간은 확인되지 않았습니다. 법령이 특정 기록의 보존을 요구하는 경우에는 해당 항목·근거·기간을 안내하고 다른 문의 정보와 분리해 보존한 뒤 기간 종료 시 파기합니다. 확인되지 않은 법정 보존 기간을 임의로 만들지 않습니다.
  • 파기 절차와 이메일 계정의 실제 설정·삭제 기능은 미검증입니다. 1년 보유 결정은 이메일 서비스의 모든 사본에 대한 삭제 보장이 아닙니다.

9. 이용자·법정대리인의 권리와 행사 방법

이용자는 개인정보 보호법에 따라 열람·정정·삭제·처리정지·동의 철회를 요구할 수 있습니다(제35조~제37조). 만 14세 미만 아동은 법정대리인이 대신 행사할 수 있습니다.

  • 앱 안의 기록: 앱 기록은 이용자 기기에 있으므로 앱 안에서 직접 지우거나 앱을 삭제하면 됩니다.
  • 개발자가 받는 정보: 문의 메일의 발신 주소·본문(앱 버전·기기 정보·재현 과정 등 이용자가 보낸 내용)·첨부입니다. 답변 목적에만 쓰며 처리 완료 후 1년 뒤 삭제합니다(8장). 이메일 서비스의 역할·확인 한계는 7장, 안전성 조치는 11장에 있습니다.

Privacy Policy

App-specific information is based on legacy code review and the App Store lookup of 2026-09-27. We have not verified that the shipped binaries match, or what the apps actually transmit. Unverified facts remain stated as limitations in this policy.

Published: 2026-09-30 · Effective: 2026-10-07 · Last revised: 2026-09-30

This policy explains what information goes where when you use the apps listed in section 1. Operator: HeungYeol Kim (individual developer). "The developer" below means this operator.

Summary

  • The developer does not run a server receiving what you type into the apps (developer confirmation on 2026-09-30). The code review also found no request from the apps to a developer-run server. Policy, support and app landing pages are hosted on GitHub Pages (section 13).
  • That does not mean nothing ever leaves your device. It differs by app: (1) apps that contain an advertising SDK (59); (2) apps that send your location, lookup terms or a vehicle identification number to an outside service so the feature can work; (3) apps that download fonts from the internet (41); (4) apps where, when you tap a share button, a record summary or file the app builds goes to the place you choose (52). Appendix A lists this per app.
  • Apps that contain the ad SDK have the code that initializes it and requests ads, so information can go to Google. In 9 of those apps the SDK is initialized before the App Tracking Transparency (ATT) prompt (section 3).
  • If you email a support request, the developer receives its contents (section 9).
  • The earlier policy mentioned "Firebase Crashlytics". We removed that: no separately added analytics or crash-reporting SDK was found in the apps covered here.

3. Advertising and tracking

  1. SDK and ad-request code. 59 apps contain the ad SDK (Google Mobile Ads; Appendix A). In the sample app checked, the banner ad unit ID is in the code and the interstitial ID is injected at build time (whether it was injected is not confirmed).

  2. The initialization order differs by app.

    • 50 apps: in code, the ATT call runs first, followed by SDK initialization and ad requests.
    • 9 apps (Fridge Reminder, White Noise, Pomodoro, Screen Detox Challenge, Holiday Reminder, Posture Reminder, Car Maintenance Log, PortCheck, Plant Watering): SDK initialization runs before the first screen appears — that is, before the ATT prompt. Pomodoro, Car Maintenance Log and PortCheck also call an interstitial preload right after initialization.
    • No code was found that reads your ATT answer and changes what the SDK does. So declining in the ATT prompt appears not to stop SDK initialization or ad requests (not measured).
    • An ATT call in the code does not mean the prompt appears every time; iOS settings and earlier answers can prevent it.

  3. What the ad SDK can process. Google's AdMob iOS data disclosure says the SDK can process:

    Category Items in Google's disclosure
    Location IP address (may be used to estimate a device's general location)
    Device ID Advertising identifier or other app- or developer-bounded device identifiers
    Advertising data Advertisements the user has seen, etc.
    Interactions App launch taps and interaction information such as video views
    Performance App launch time, hang rate, energy usage, etc.
    Diagnostics Crash logs

    We have not verified, by observing traffic (a proxy) or by checking the Privacy Manifest, which of these items the shipped builds actually send or when. Based on Google documentation; actual transmission is unverified. Declining ATT is not evidence that all SDK transmissions stop.

  4. Separately added analytics vs. the ad SDK itself. No analytics or crash-reporting SDK added by the developer (Firebase, Sentry, etc.) was found in the dependencies reviewed for the 61 apps, and no code sending app-usage records to the developer was found. As item 3 explains, the ad SDK itself can send diagnostic, performance and interaction information to Google.

  5. ATT settings. The prompt mentions "relevant ads". If you decline, the app cannot access IDFA (see the SDK limitations in item 3). Change this in Settings → Privacy & Security → Tracking.

  6. Apps without the ad SDK: Fasting Window (no ads, no ATT), and Workout Log (no ad SDK; it includes the ATT package but never calls it).

  7. The App Store "App Privacy" label lists "Data Used to Track You: Identifiers" or similar for most apps that contain the ad SDK (Fasting Window and Workout Log say "Data Not Collected"). The labels will be changed when rebuilt versions without the SDK ship. A final per-app comparison of the store privacy labels against this policy has not been performed.

5. Location, camera, photos, files, sharing

  • Location (5 apps):
    • Mosquito Weather, Morning Briefing, Air Quality and Outdoor Go Advisor send coordinates to Open-Meteo for weather and air quality; the Air Quality app also converts coordinates to TM coordinates and sends them to the Air Korea service (data.go.kr) to find the nearest monitoring station.
    • The Parking Timer app downloads map tiles from OpenStreetMap servers, so the tile coordinates of the map area you view and your IP go there.
    • The Parking Timer stores the latitude and longitude of where you parked on your device (current session, history, favorites; SharedPreferences). When you tap navigate, the saved coordinates are passed to the iOS Maps app, or, if it cannot open, put into a Google Maps address that is opened. We did not check how that app or service handles the coordinates afterwards. This storage and handoff happens between your device and the app you opened, not through a developer server. Retention differs by kind of storage. The current parking session is cleared when parking ends, and its coordinates are moved into recent history. Recent history keeps at most 20 entries; beyond 20, the oldest entries are automatically dropped from the app's stored list and their photos are cleaned up. This automatic drop is by the app's stored list; it is not a guarantee that the data is unrecoverably erased from device storage, and it does not reach separate copies such as iOS or iCloud backups. Favorites remain until you delete them or delete the app. We have not verified which stored items the history/favorites deletion screens remove.
    • The Air Quality app stores the coordinates of favorite cities you add on your device.
    • No code storing coordinates was found by static search in the other three location apps (Mosquito Weather, Morning Briefing, Outdoor Go Advisor).
    • Coordinates are not stored on a developer-run server. The earlier policy did not mention location.
  • Camera / photos: 4 apps (QR Menu Maker, Real Estate Note, Parking Timer, Plant Watering) use an image picker.
  • Files: D-Day uses a file picker (backup import).
  • Sharing: 52 apps contain code that opens the share sheet (Appendix A). When you tap a share button, text, an image or a file the app builds at that moment (for example a record summary, a QR image, a backup) goes to the app or service you choose. The developer does not receive it; how that copy is kept or deleted follows the policy of the place you chose.
  • You can turn these permissions off in iOS Settings; only the related feature stops working. Actual behavior after permission denial has not been tested per app.
  • 59 apps contain a permission-prompt string that mentions "microphone access", but no microphone feature is used (the wording is inaccurate); the prompt never appears.
